Detalhamento Prático das Vulnerabilidades OWASP Top 10

Procedimentos de segurança e correção de vulnerabilidades em código. Um guia passo a passo estruturado do nível Júnior ao Especialista para remediação ativa.

A03:2021 — SQL Injection (SQLi)

Dados não sanitizados fornecidos pelo usuário são avaliados pelo interpretador como comandos estruturados.

1. Júnior (Procedimentos de Triagem e Boas Práticas Básicas)

  • Identificação: Localize queries construídas por concatenação manual de strings (ex: "SELECT * FROM users WHERE email = '" + email + "'").
  • Ação Corretiva: Substitua consultas vulneráveis por chamadas nativas parametrizadas do ActiveRecord ORM (ex: IamUser.find_by(email: email) ou where("email = ?", email)).

2. Pleno (Auditoria SAST/DAST e Hardening)

  • Pipeline de Testes: Integre ferramentas de análise estática como o Brakeman (para Ruby) ou SonarQube no pipeline de CI/CD para bloquear deploys contendo concatenações cruas.
  • Hardening: Defina limites de tamanho estritos para todos os inputs textuais no nível do schema e adicione validações Regex para rejeitar caracteres de controle SQL.

3. Especialista (Segurança de Banco e Defesas Ativas)

  • Princípio do Menor Privilégio: Crie credenciais de banco exclusivas para a aplicação com permissões restritas (remover direitos de DROP, ALTER e acessos a schemas de sistema).
  • WAF: Configure assinaturas de decodificação no Web Application Firewall (WAF) corporativo para interceptar e bloquear padrões SQLi antes de atingir os servidores de aplicação.

A01:2021 — Controle de Acesso Quebrado (IDOR & Privilege Escalation)

Falhas de design ou implementação que permitem que um usuário acesse ou modifique dados fora de seu privilégio.

1. Júnior (Controles de Roteamento)

  • Mapeamento: Garanta que todas as rotas API comecem com verificações de autorização de sessão (ex: session[:user_id]).
  • IDOR: Nunca confie puramente em IDs numéricos sequenciais passados pela URL. Valide se o registro pertence ao usuário logado: 
    # Inseguro: Ticket.find(params[:id])
# Seguro: current_user.tickets.find(params[:id])

2. Pleno (RBAC & Validações de Escopo)

  • RBAC Estruturado: Centralize as políticas de permissão em módulos reutilizáveis.
  • Auditoria: Crie rotas dedicadas a Auditoria e IGA que façam checagem recursiva de privilégios de acesso e gerem logs imutáveis de cada requisição.

3. Especialista (Políticas RLS & Governança IGA)

  • Row-Level Security (RLS): Se utilizando PostgreSQL ou Oracle, ative RLS diretamente na tabela para que o próprio interpretador SQL impeça a leitura de linhas não autorizadas.
  • Integração Sailpoint IGA: Automatize ciclos de certificação e provisionamento dinâmico para revogar permissões não utilizadas de forma tempestiva.
